# App Review Notes

This file is what we hand to Apple App Review and Google Play Policy reviewers when submitting version 1.0.0 of **Dead Air Radio**. It heads off the common review rejections that have historically hit atmospheric-horror and audio-driven apps.

> Keep this file in sync with [`app-privacy.md`](./app-privacy.md) and the contents of `lib/analytics.ts` / `lib/errorTracking.ts`. Reviewers cannot be lied to — every claim here is verifiable from the source.
>
> Include the full text below in the _App Review Information → Review Notes_ field on App Store Connect, and in the _Notes for Google Play review_ field on the Google Play Console.

---

## Summary

**Dead Air Radio** is a single-player narrative horror game. The player is a fictional late-night DJ. Players tune a simulated radio dial, answer procedural "calls", and slowly fill a tape archive. There is no real-world broadcast reception and no real-world telephony.

## It's a game, not a real radio

- The dial UI in `app/radio/index.tsx` is a stylized on-screen tuning control. It tunes **internal simulated frequency bands**, not real RF or internet radio streams.
- The "frequency display" (e.g. 88.7 FM, 102.3 FM, 117.8 AM) is a thematic label. No audio is received from any external broadcast source at any point.
- No media player or radio streaming API is invoked. All audio is generated by the in-app Web Audio engine — see `engine/audio/` in the source.
- The app does **not** stream, decode, or re-broadcast any real-world AM/FM/internet audio.

## Audio is synthesized, not real broadcasts

- All caller voices, static, scanlines, and ambient beds are produced at runtime by the on-device audio engine in `engine/audio/`. They are not clips from any third-party library.
- The `RECORD_AUDIO` / `NSMicrophoneUsageDescription` permission is used only for real-time audio **processing** of the microphone input through the audio engine's voice-processing chain. Audio is **not recorded**. Audio is **not stored**. Audio is **not transmitted**. Looking at the code in `lib/errorTracking.ts`/`lib/analytics.ts` confirms nothing audio-related ever leaves the device or the audio rendering graph.

## No user-generated content

- The 18 caller scripts (`data/calls.js`) are **pre-written, fixed content**. No caller copy is generated from user input, except the **optional** Infinite Signal AI mode (see below), where a Claude API call generates new callers purely for the local player who unlocked it. The generated content is never shared, posted, or transmitted to other players.

## No social features

- There is no friend list, no chat, no posting, no leaderboard, no profile sharing, no multiplayer server.
- The Settings screen exposes an in-app Reset and an opt-out for analytics only. There is no way for one player to contact another player through the app.

## No payments beyond the two IAPs

Only two IAP products exist:

| Product ID          | Platform SKU             | Purpose                                     | Type                    |
| ------------------- | ------------------------ | ------------------------------------------- | ----------------------- |
| `dead_air_base`     | App Store / Play Console | Unlock the full base game                   | One-time non-consumable |
| `dead_air_infinite` | App Store / Play Console | Unlock Infinite Signal (AI-generated calls) | One-time non-consumable |

- No consumables, no gems, no coins, no lootboxes.
- No subscription products of any tier.
- No "free trial" wrapped into a paid subscription.
- No advertising.
- The base game and Infinite Signal can both be **restored** by the platform's restore-purchases flow.

## Infinite Signal AI mode (only if the IAP is unlocked)

- Only available after the `dead_air_infinite` IAP is purchased.
- Sends the player's current radio context to a Claude API endpoint, proxied via Cloud Run (`proxy/index.js`, configured via `EXPO_PUBLIC_API_URL`). The proxy receives no identity data, only the request body for "give me one new caller given this band/state".
- The generated call is shown to the local player only; it is not stored server-side, not shared, and not posted anywhere.
- All content from the AI mode is governed by Anthropic's content policy and our proxy's own refusal path.

## Content considerations for the reviewer

This app deals with **psychological horror**, **grief**, **death**, **the supernatural**, and **classified briefing-style voice work**.

- No jump scares. The horror is quiet, ambient, and dialog-driven.
- No graphic violence. No blood, no gore, no weapons.
- No sexual content.
- No drug use.
- Mild profanity only when caller scripts call for it.
- A **content warning** is shown at first launch and from Settings → About, before any thematic content plays.

The App Store rating we have declared is **12+** for infrequent horror/fear themes. Google Play rating is **Teen** via IARC. Both are conservative — the actual content is closer to a YA horror short story collection.

## Demo mode for reviewers

- No login required. The game opens to the radio screen immediately.
- Reviewers can unlock all bands by tapping Settings → (long-press on version label 5×) → "Reviewer Mode". This unlocks all 5 bands for the current session and is **not gated behind an IAP**. It exists only to let the reviewer see every screen quickly without grinding the band-unlock progression. The same code path is used by the in-game QA build profile (`__tests__/platform/`).
- The IAP products `dead_air_base` and `dead_air_infinite` can be tested with App Store sandbox / Google Play license-test accounts.

## Permissions

### iOS

- `NSMicrophoneUsageDescription`: Used for voice processing in the audio engine. _Not_ for recording audio. Audio is not stored. Audio is not transmitted.
- `UIBackgroundModes: ["audio"]`: Required to keep the radio audio bed playing when the screen locks.

### Android

- `RECORD_AUDIO`: Same purpose as iOS microphone.
- `FOREGROUND_SERVICE`: Audio playback continuation when the app is backgrounded.
- `FOREGROUND_SERVICE_MEDIA_PLAYBACK`: Android 14+ requirement for the playback foreground service type.

No other permissions are requested. There is no camera, no location, no coarse/fine location, no contacts, no storage, no phone state.

## Where the data goes (one-line)

> The app stores local save and (if opted in) local analytics on-device. Crash reports go to Sentry. No other party receives any user data. See [`app-privacy.md`](./app-privacy.md).
